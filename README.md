# Kema · Blood Tests — متابعة التحاليل

موقع عربي لمتابعة نتائج التحاليل والأدوية عبر الوقت. يدعم وضعًا محليًا مستقلًا، ووضع Cloudflare بحساب خاص ومزامنة بين الأجهزة. مبني بـ HTML وCSS وJavaScript وSVG، مع عارض PDF.js مضمن محليًا.

## مشروع Cloudflare والملفات الصحية

- الموقع: https://kema.ahmedmansor.workers.dev/، على Worker باسم `kema` مع D1 `kema-db` ومخزن R2 خاص `kema-pdfs`.
- Cloudflare Access يتحقق من الإيميل بكود بريد. قائمة الدخول ما زالت محددة بالإيميلات في سياسة Access؛ التسجيل العام المفتوح غير مفعّل. دخول حساب مسموح جديد لا يمنحه أي سجل قديم: إذا لم تُشارك معه ملفات، يُنشأ له ملف شخصي فاضي.
- كل ملف له مالك وأعضاء مستقلون: المالك يعدّل ويشارك؛ editor يعدّل النتائج والأدوية ويرفع الملفات؛ viewer يقرأ ويقارن ويطبع ويصدّر فقط. ملكية حساب Cloudflare لا تتجاوز صلاحيات الملفات في واجهة API. كل حساب يرى الملفات التي يملكها أو التي شاركها أصحابها معه فقط.
- التبديل من زر «الملف» أعلى الموقع أو «حسابي → ملفاتي الصحية». إنشاء ملف إضافي يبدأ ببيانات فارغة. التبديل يعيد تحميل الصفحة مع اختيار الملف، ويُمنع عند وجود مزامنة معلقة أو تعارض حتى تُراجع التغييرات.
- المشاركة من «حسابي → مشاركة هذا الملف»: إضافة إيميل بصلاحية قراءة أو تعديل أو إلغاء مشاركته. مشاركة الملف لا تسمح بالدخول إلى الموقع وحدها؛ الإيميل يحتاج أيضًا السماح به في Access. الإلغاء وتغيير الدور يُفحصان في كل طلب، بما في ذلك الجلسات الصادرة سابقًا.
- كل مسارات البيانات والمرفقات والجلسة والأعضاء تحمل معرّف الملف تحت `/api/profiles/:id/…`. طلب ملف غير مسموح يرجع 404 قبل قراءة بياناته أو R2. المسارات المشتركة القديمة مثل `/api/state` مقفولة بـ409 لتمنع النوافذ القديمة من الحفظ في سجل خاطئ.
- الجداول: `kema_profiles` و`kema_profile_members` و`kema_profile_state` و`kema_profile_history`. الحفظ برقم إصدار يمنع الكتابة فوق تعديل جهاز آخر؛ يحتفظ كل ملف بآخر 30 نسخة سابقة مستقلة.
- مفاتيح R2 تبدأ بمعرف الملف ثم بصمة PDF. لا يمكن ربط ملف مرفوع في ملف صحي آخر، حتى مع معرفة بصمته. الحد 15 ميجابايت للمرفق و1 ميجابايت لسجل النتائج المتزامن. الاستخراج بالذكاء الاصطناعي غير مفعّل.
- التخزين المحلي وIndexedDB وطابور المزامنة ونسخ الاسترجاع ومؤشر النسخ الاحتياطي منفصلة حسب الإيميل والملف. لا تُقرأ ذاكرة ملف قبل التحقق من هوية الحساب وعضويته. البيانات القديمة بالمفتاح المشترك لا تُدمج تلقائيًا مع أي ملف جديد، وتُترك محفوظة على الجهاز. النسخ المحلية ليست بديلًا عن حماية الجهاز، والنسخ التي نُزّلت سابقًا لا يمكن سحبها عن بُعد.
- «حسابي» يعرض الإيميل وصلاحيتك في الملف وبداية الجلسة وانتهاءها من JWT المتحقق، دون إرسال الرمز للواجهة. الجلسات الجديدة مدتها 720 ساعة؛ الجلسات القديمة تحتفظ بانتهائها الأصلي. إعداد الجلسة العام للمؤسسة لم يتغير.

### الترقية والنشر

لإعداد قاعدة جديدة طبّق `cloudflare/profiles-schema.sql`. لترقية النسخة المشتركة القديمة طبّق الجداول الجديدة ثم عبارات `legacyProfileMigration(ownerEmail)` في `cloudflare/migrate-profiles.mjs`؛ الترقية إضافية وقابلة للتكرار، وتحتفظ بجداول المصدر كما هي. انسخ المستندات القديمة إلى مفاتيح R2 المسبوقة بمعرف الملف قبل ترقية أي تثبيت له مرفقات؛ تثبيت Kema الحالي كان بلا مرفقات وقت الترقية. لا تُعد نشر إصدار الخادم المشترك القديم بعد بدء استخدام الملفات المستقلة.

نُقل السجل الحالي إلى `family-main` مع الحفاظ على النتائج الـ75 وصلاحية المشاهدة القائمة. جُهز ملف منفصل وفارغ للوالد تحت حساب المستخدم، بدون مشاركة جديدة أو نتائج وهمية. تم التحقق من التبديل بين الملفين على الموقع ومن تطابق سجل النتائج مع المصدر القديم.

الخادم يحتاج `ACCESS_TEAM` و`ACCESS_AUD` وتطبيق Access على الدومين. السر القديم `OWNER_EMAIL` لم يعد يمنح صلاحيات عامة؛ ملكية كل ملف محفوظة في D1. بعد `npm ci` وتفويض Wrangler استخدم `npm run deploy:cloudflare`. افحص بدون نشر بـ`npm run check:cloudflare`. البناء يضم ملفات التطبيق فقط، ويستبعد `data/` و`artifacts/` والأسرار. ملفات JSON الطبية لا تدخل الريبو أو البناء العام.

## التشغيل

تحتاج Node.js 20 أو أحدث. من مجلد المشروع:

على ويندوز يمكنك الضغط مرتين على `Start Kema.cmd`: يشغل الخادم ويفتح الموقع في المتصفح. اترك نافذة التشغيل مفتوحة أثناء الاستخدام. أو شغله بالأمر:

```powershell

```

افتح http://127.0.0.1:5173. يجب استخدام نفس العنوان والمتصفح للاحتفاظ بالسجل نفسه؛ localhost و127.0.0.1 لهما تخزين منفصل.

الخادم يقرأ بيانات البداية من `data/initial-results.json` عند أول فتح فقط. هذه البيانات مأخوذة من CSV المرفق: 75 نتيجة، 13 تاريخًا، و14 اسم ملف مصدر. الأدوية تبدأ فارغة. الأرقام معتمدة كما قدمها المستخدم. ملفات PDF غير مرفقة.

## المزايا

- آخر النتائج ومقارنتها بالقياس السابق.
- منحنيات زمنية بمسافات حقيقية بين التواريخ، مع تفاصيل كل نقطة وجدول بديل.
- رسم منفصل لكل تحليل ووحدة، مع فلترة الفترات من أحدث قياس للتحليل.
- البحث والتصنيف وفلترة التاريخ والحالة في السجل.
- إضافة وتعديل وحذف النتائج وإضافة أنواع تحاليل أخرى.
- تسجيل الأدوية والجرعات والفترات، وتظليلها على الرسوم المطابقة.
- نسخة JSON كاملة تشمل النتائج والأدوية والاسم؛ CSV للنتائج فقط.
- استيراد CSV أو JSON مع معاينة ودمج، ومنع تكرار السجلات المتطابقة.
- التحقق من التواريخ والأرقام، وتجاهل حدود المرجع الفارغة، وعدم خلط الوحدات.

## تحسينات تجربة الاستخدام

- **تقرير كامل:** إدخال التاريخ والمعمل والطبيب مرة واحدة مع عدة نتائج، وإرفاق PDF اختياري. تُتجاهل الصفوف الفارغة ويُرفض التقرير كله إذا احتوى صفًا غير صالح. المرجع يكتب من التقرير، ولا يُفترض من قياس سابق.
- **تاريخ البطاقات:** يظهر تاريخ أحدث قياس على كل بطاقة؛ المقارنة السابقة لنفس الوحدة فقط.
- **مقارنة التحاليل:** تبدأ باختيار تحليل ووحدة لهما قياسان مسجلان على الأقل، ثم اختيار قياسين موجودين فعلًا لهذا التحليل فقط. في وضع الزيارات تظهر الزيارة الثانية فقط إذا كان بها تحليل مشترك قابل للمقارنة مع الأولى؛ الجدول يعرض المشترك فقط. لا تُقارن وحدات مختلفة، ولا يُختار قياس عشوائي عند وجود عدة قياسات في نفس الزيارة، ولا تحسب نسبة أساسها صفر. الصائم والفاطر نوعان منفصلان. الألوان لا تعني تحسنًا أو تراجعًا.
- **ملخص الطبيب:** اختيار فترة وتصنيف، ثم معاينة تشمل النتائج وفترات الأدوية المتقاطعة والمنحنيات. زر الطباعة يفتح طباعة المتصفح، ومنها يمكن اختيار حفظ PDF. الأصول المرفقة لا تدخل في طباعة الملخص.
- **المحذوفات:** نقل النتائج والأدوية إلى سجل استرجاع دائم في المتصفح، مع زر تراجع مباشر. لا يحذف التطبيق ملفات PDF عند نقل نتيجة؛ المرفق يرجع مع استعادتها.
- **حالة النسخ الاحتياطي:** وقت آخر تنزيل كامل ومؤشر تغييرات منذ النسخة. تنزيل CSV أو JSON بدون PDF لا يغيّر مؤشر النسخة الكاملة. المؤشر يثبت تجهيز التنزيل، وليس تحقق حفظ الملف فعليًا على القرص.

## مرفقات PDF

تُحفظ الملفات في IndexedDB الخاص بنفس أصل المتصفح، بحد **15 ميجابايت للملف**. تستخدم بصمة SHA-256 لتجنب تخزين محتوى مطابق مرتين والتحقق من الملفات أثناء استعادة JSON. يدعم العارض المحلي الصفحات والتكبير وملاءمة العرض وكلمات المرور؛ المراجعة اليدوية تعدّل النتيجة والوحدة والمرجع بجانب الأصل.

يمكن ربط PDF بنتائج قديمة باختيار التاريخ والنتائج المقصودة. هذا **إرفاق وعرض ومراجعة يدويّة**، وليس استخراج AI أو OCR.

عارض [Mozilla PDF.js](https://mozilla.github.io/pdf.js/) إصدار **6.4.299** مضمن في `public/vendor/pdfjs` مع خطّه العام وملفات الخطوط وخرائط الأحرف وWASM. رخصة Apache-2.0 محفوظة في نفس المجلد. لا تُحمّل مكتبة أو خط من CDN أثناء الاستخدام. تأكد عند الاستضافة من تقديم ملفات `.mjs` بنوع JavaScript و`.wasm` بنوع `application/wasm`.

## الحفظ والخصوصية

البيانات محفوظة في localStorage والمرفقات في IndexedDB على هذا المتصفح، وليست مشفرة ولا محمية بحساب دخول. الجهاز المشترك يتطلب مراعاة من يمكنه فتح المتصفح. مسح بيانات الموقع أو تغيير المتصفح يفصل السجل؛ صدّر JSON الكامل لاستعادته أو نقله. لا توجد مزامنة تلقائية بين الأجهزة. لا يحتوي المصدر العام على بيانات طبية؛ بيانات البداية تحت `data/` مستبعدة من Git والبناء. الخادم المحلي يستمع على 127.0.0.1 فقط.

استيراد النسخة يدمج السجلات ولا يمسح القديم. القياسات المختلفة بنفس التاريخ تُحفظ كقياسات مستقلة. **JSON الكامل يشمل المرفقات والمحذوفات**، بينما CSV يشمل النتائج فقط، وJSON بدون PDF يحتفظ ببيانات السجل وروابط المرفقات دون محتوى الملفات. حد حجم نسخة الاستيراد والتصدير **100 ميجابايت**. النسخ القديمة متوافقة وتُفتح دون تغيير الأرقام. عند غياب ملف مرفق لا يدّعي التطبيق تصدير نسخة كاملة؛ يوضح المشكلة ويتيح تصدير البيانات فقط. كل التنزيلات تحتاج الاحتفاظ بها في مكان خاص.

المقارنة هي بمرجع البيانات المرفقة وبحدود شاملة للطرفين. لا يستنتج التطبيق تشخيصًا أو هدفًا علاجيًا. عمودا CSV الرقميان لا يحتفظان بعلامات `<` أو `>` الموجودة في تقارير أصلية غير مرفقة.

## التحقق والبناء

اختبارات الخادم السحابي تستخدم SQLite المضمنة في Node.js؛ استخدم Node.js 24 للاختبارات.

```powershell
npm test
npm run build
```

`dist/` يحتوي التطبيق فقط دون الاسم أو نتائج البداية. النشر الحالي من فرع `gh-pages` على GitHub Pages. لتحديث الموقع بعد تعديل الكود، شغّل `powershell -ExecutionPolicy Bypass -File scripts/publish.ps1`؛ يختبر التطبيق ويبني وينشر `dist/` فقط. الدفع إلى `main` يحفظ المصدر ولا يحدّث الموقع وحده. عند استنساخ الريبو من جديد نفّذ أولًا `git fetch origin gh-pages:gh-pages`. بيانات البداية والمرفقات والنسخ الاحتياطية المحلية مستبعدة من Git. الموقع المنشور يبدأ فارغًا في كل متصفح جديد: استورد نسخة JSON الخاصة من داخل المتصفح المقصود. لا تنتقل بيانات المتصفح المحلي تلقائيًا إلى نطاق GitHub Pages، ولا تتزامن الإضافات بين الكمبيوتر والموبايل في هذه النسخة.

مهارة التصميم التي طلبها المستخدم مثبتة محليًا في `tools/skills/ui-ux-pro-max`، وستكون قابلة للقراءة من هذا المسار في الأدوار التالية؛ ليست مثبتة كتفضيل عام لحساب Codex. قرارات التصميم محفوظة في `design-system/kema/MASTER.md`.

## الزيارات والروشتات

داخل كل ملف صحي، قسم «الزيارات والروشتات» يحفظ أطباء وتخصصات وزيارات مرتبطة ببنود الدواء والتشخيصات وطلبات الفحوص والتنبيهات والمواعيد. البيانات في `clinical` داخل سجل الملف في D1؛ تخضع لنفس الصلاحيات والمراجعات والمزامنة والنسخ الاحتياطية. الروابط بين العناصر تُفحص عند الحفظ والاستيراد، والدمج يعالج تصادم المعرّفات دون ربط عناصر بزيارة خاطئة.

تاريخ الروشتة مستقل عن فترة تناول الدواء. يمكن حفظ تاريخ زيارة أو سنة موعد غير معروفين دون تخمين. «تسجيل فترة تناول فعلية» يضيف تسجيلًا مستقلًا إلى الأدوية والرسومات بعد إدخال الجرعة والتواريخ الفعلية. لا يحوّل الاستيرادُ الروشتات القديمة إلى أدوية مستمرة تلقائيًا. البيانات المنقولة تحمل مصدرها وحالة مراجعتها، والشروح المنقولة تُعرض بهذه الصفة. اختيار «راجعت البيانات على المصدر الأصلي» متاح عند تعديل الزيارة.

السجل الطبي الجديد يدخل في النسخة الاحتياطية الكاملة ودمج الاستيراد؛ لا يدخل تلقائيًا في روابط الطبيب أو تقارير التحاليل الحالية. لا تنشر بيانات الإدخال الخاصة أو ملفات SQL الطبية في Git أو مجلدات البناء. يحفظ الخادم نسخة سابقة من سجل الملف، ويرفض كتابة عميل قديم يُسقط حقل السجل الطبي.

## استخدام تقرير الطبيب

في نسخة Cloudflare، اختر الملف الصحي أولًا. زر «تقرير PDF للطبيب» يجهّز أحدث زيارة، وكل المنحنيات، والسجل في الفترة المختارة. من المعاينة اضغط «حفظ PDF / طباعة» ثم اختر حفظ كملف PDF في المتصفح.

صاحب الملف وحده يستطيع إنشاء «مشاركة للطبيب»: نسخة ثابتة للقراءة فقط، لمدة 24 ساعة أو 3 أيام أو 7 أيام، قابلة للإلغاء. لا يحتاج الطبيب حسابًا، وأي شخص معه الرابط يستطيع قراءة النسخة حتى انتهائها أو إلغائها. النسخة لا تشمل المرفقات الأصلية أو الملاحظات أو ملفات أشخاص آخرين، وإلغاء الرابط لا يسحب نسخة سبق تنزيلها. الاسم والأدوية اختيارات واضحة قبل الإنشاء.

العارض على Worker مستقل `kema-share`؛ يحفظ الخادم تجزئة الرمز فقط، ويوضع الرمز في جزء الرابط بعد `#`. لا تُعدّل حماية Access للتطبيق الرئيسي. تهيئة الجدول: `npx wrangler d1 execute kema-db --remote --file cloudflare/shares-schema.sql`. نشر العارض: `npm run deploy:share` ثم التطبيق: `npm run deploy:cloudflare`. كلا البناءين يستبعدان البيانات الطبية. اختبارات المشاركة تعمل على بيانات مصطنعة داخل SQLite محلية؛ لا تنشئ روابط حقيقية للسجل أثناء الاختبار.
